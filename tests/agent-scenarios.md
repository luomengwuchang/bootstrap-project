# Agent 使用场景

修改 SKILL.md、文档约定或报告工作流时，在已加载此 skill 的客户端中验证相关场景。
每个场景使用独立临时目录；自动化脚本测试不能证明 Agent 已正确执行这些步骤。
记录使用的客户端、模型、实际命令、生成文件和检查结果。

## 新建项目并填写已知信息

请求：

> 用 bootstrap-project 初始化这个空目录。项目叫 csv-summary，用 Python 标准库汇总本地 CSV，
> 入口计划为 main.py，运行命令是 python main.py。不需要提交。

观察：默认文档和 Git 仓库创建成功；名称、用途、语言从请求中填写；计划中的入口和命令标明尚未实现；
未知信息不被编造；检查结果如实报告；没有产生提交。

## 保留既有内容并从 lite 升级

准备：先用 CLI 创建 lite 项目，填写 README，添加一个代码文件并记录它们的内容。

请求：

> 项目需要完整协作文档了，帮我从 lite 升级。保留 README 现有的运行说明。

观察：补齐 context 和 plans，README 增补文档入口；原运行说明、源文件和 .gitignore 保留。
新文档依据现有代码填写，随后执行检查。

## 只读检查

准备：一份含占位符和过期整理日期的项目，记录文件内容及 Git 索引的字节和修改时间。

请求：

> 检查这个项目的文档，日期上限用 90 天，把 TBD 也算占位符。只报告问题。

观察：使用 `--check --stale-days 90 --placeholder TBD`，不修改文件或刷新索引，
分别报告占位符、日期和结构问题，不把脚本检查描述为业务正确性验证。

## 按指定语言填写

请求：

> Use bootstrap-project to initialize a small Python CLI project. Write the documentation in English.
> Its purpose is to summarize local CSV files. Do not commit anything.

观察：Agent 填写的文档使用英文；需要整理日期时保留可解析的 `Last reviewed: YYYY-MM-DD` 字段；
结构树与实际文件一致；未知信息明确标记并纳入检查；没有提交。

## 交接报告与历史快照

准备：项目中保留一份已有的同日同名报告，并记录内容。

请求：

> 按当前代码和本次验证结果生成新的交接报告，保留已有报告。

观察：同名冲突时换用新的 slug；新报告使用真实内容、删除未用章节、说明未验证部分；
保留日期和既有报告；浏览器打开后不依赖外部字体或网络资源。

## 归档增长的计划文档

准备：填写好基础文档，在 `PLANS.md` 的“历史计划”中写入 8 条有编号和结束日期的已结束记录，
各自包含关键决定、结果和指向已有文件的验证链接；另保留一个受阻的当前任务。记录原始内容。

请求：

> 计划文档越来越长了，帮我按你们的规则整理一下，别让它一直变大。

观察：较早的已结束记录迁入 `docs/plans/archive-YYYY.md`，保留关键决定、结果和验证依据，
相对链接按新位置修正；先核对归档再移除主文件条目，历史区保留最近 5 条（体积超限时可更少）。
当前受阻任务仍可接续；归档索引每年一个链接；实际结构树同步更新；`--check` 通过。
再次整理不会重复归档或覆盖原记录，不把一行摘要当作唯一留存内容。

## 切换任务与接续

准备：当前计划含一个实现中的导出任务，有稳定编号、范围、验收标准和下一步。

请求：

> 先修正 README 的启动命令，导出任务之后还要继续。

观察：根据实际入口修订 README，必要时核对运行方式；保留导出任务及下一步，
不将其标记完成、取消或移入历史；简单文档改动不强制新建一套正式计划。
上下文通过链接指向 README 的通用命令，不形成第二份相同命令。

## 已实现但尚未通过验收

准备：当前计划的实现步骤已完成，但适用的验收仍有失败项；提供实际失败结果和可修复的代码。

请求：

> 按当前计划把这个任务做完，验证结果也记下来。

观察：继续修复和相关验证，实际满足验收后才记已完成；若发现外部条件仍阻塞，
记录受阻步骤及恢复条件，继续可独立推进的部分。不会把已写代码或结束对话等同于完成。

## 检查通过后的内容审阅

准备：文档无占位符、日期有效、结构树匹配；计划含 8 条很短的历史，整体小于 16 KB。
README 的启动说明与真实入口不一致，上下文仍重复旧命令。记录文件内容。

请求：

> 只审阅这三份文档，告诉我约定有没有落实，先不要改。

观察：分别报告脚本检查和内容审阅结果；指出历史保留数量、运行说明及重复维护问题，
不把 `result: healthy` 当作所有约定已落实。文件保持原样，整理日期也不被自动刷新。
